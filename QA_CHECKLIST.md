# Portfolio QA Checklist

## Purpose
Use this checklist after portfolio changes that can affect layout, typography, shared components, responsive behavior, generated output or public deployment.

## Source integrity
- [ ] Confirm the authoritative source file before editing.
- [ ] Do not treat `docs/` as the source when the file is generated by the build.
- [ ] Confirm root-page and `src/` source responsibilities before changing duplicated-looking files.
- [ ] Run the normal build/check pipeline after source changes.

## Visual unit policy
- [ ] Active `font-size` fixed/min/max values use px, not rem/em.
- [ ] Responsive typography uses px bounds, e.g. `clamp(px, calc(px + vw), px)`.
- [ ] Active `letter-spacing` uses px unless a documented exception exists.
- [ ] Text-shadow and box-shadow offset/blur/spread use px.
- [ ] Border/hairline thickness uses px where visual shape should remain stable.
- [ ] Unitless `line-height` is preferred unless a verified fixed treatment is required.
- [ ] Layout dimensions were not converted to px unnecessarily.

## Shared typography
- [ ] Common body text uses the intended shared token.
- [ ] Japanese and English normal body-copy pairs use the same `--font-body-size`; translations are not accidentally using caption sizing.
- [ ] Common links/UI text use the intended shared token.
- [ ] Header navigation and footer navigation use the same type token inside each breakpoint.
- [ ] Page-specific overrides are justified and do not duplicate an existing shared role.
- [ ] Shared-token changes have been checked against every consumer.

## Breakpoints
Verify at minimum:
- [ ] 1440px
- [ ] 1280px
- [ ] 1024px
- [ ] 768px
- [ ] 430px
- [ ] 390px
- [ ] 375px

Shared breakpoint model:
- Mobile: `<= 599px`
- Tablet: `600px - 1298px`
- Desktop: `>= 1299px`

## Typography and layout
- [ ] No unintended line wrapping.
- [ ] No clipped text.
- [ ] No horizontal overflow.
- [ ] English and Japanese text remain readable.
- [ ] Tables remain readable and do not overflow.
- [ ] Form labels, inputs, helper text and validation remain legible.
- [ ] Gallery metadata/captions remain readable.
- [ ] Header/footer remain balanced and visually consistent.
- [ ] 404 and exhibition pages follow the same shared system unless intentionally documented.

## Interaction and accessibility
- [ ] Keyboard focus remains visible.
- [ ] Touch targets remain usable.
- [ ] No interaction is hidden by responsive changes.
- [ ] Reduced-motion behavior remains valid.
- [ ] Hover-only behavior is not required for essential information.

## Runtime checks
- [ ] No page errors.
- [ ] No console errors introduced by the change.
- [ ] No failed critical resources.
- [ ] Internal navigation still works.
- [ ] Forms and modal controls still work where affected.

## Visual Regression and deployment
- [ ] Follow the canonical sequence and Linux screenshot-baseline policy in `AGENTS.md` → `Visual Regression standard`.
- [ ] Keep screenshot comparison enabled for the formal Visual Regression run and classify any differences before a baseline update.
- [ ] For breakpoint-sensitive work, use the full seven-viewport matrix.
- [ ] Build and repository checks pass before Visual Regression.
- [ ] GitHub Pages build and deploy pass after Visual Regression.
- [ ] Confirm the deployed public URL at the affected routes and viewports; use a cache-busting URL or hard reload when verifying fresh CSS.
