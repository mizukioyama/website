# Site Map and Change Map

This file records the verified source -> build -> docs mapping. Re-check webpack.config.js and package.json whenever the build architecture changes.

## Architecture

### Root visual pages
The following root HTML files are the visual source of truth and are copied verbatim by CopyWebpackPlugin into docs/:

- index.html -> docs/index.html
- artist-statement.html -> docs/artist-statement.html
- biography.html -> docs/biography.html
- order.html -> docs/order.html
- gallery.html -> docs/gallery.html
- contact.html -> docs/contact.html
- policy.html -> docs/policy.html

Their root CSS directory is copied as css/ -> docs/css/.
Only the scripts listed in rootVisualScripts in webpack.config.js are copied from js/ -> docs/js/.
The shared navigation/footer/sidebar markup used by these root pages is generated in js/menu.js, so changes to the root-page header/footer must be made there rather than in docs/.

### Webpack template pages
The following pages are generated by HtmlWebpackPlugin and receive the current Webpack bundle:

- src/information.html -> docs/information.html
- src/matching.html -> docs/matching.html
- src/bot.html -> docs/bot.html

src/index.js is the application entry. Its imported styles and scripts are bundled to:

- docs/js/main.js
- docs/styles/main.css
- code-split chunks emitted by Webpack when dynamic imports are used

Page-specific imports are selected from body[data-page].

### Shared fragments for Webpack pages
These fragments are copied by CopyWebpackPlugin:

- src/header.html -> docs/header.html
- src/footer.html -> docs/footer.html
- sidebar.html -> docs/sidebar.html

src/js/all.js fetches header.html for pages containing #header-container.
src/js/side-foot.js fetches footer.html and sidebar.html when their target containers exist.
CSP hashes for the copied footer fragment must be calculated from src/footer.html.

### Static deployment files and assets
- robots.txt -> docs/robots.txt
- sitemap.xml -> docs/sitemap.xml
- img/ -> docs/img/
- src/assets/images/ -> docs/assets/images/
- img/web.ico -> docs/favicon.ico and docs/assets/images/pd.ico

## Build and deployment
package.json defines the canonical validation path:

1. npm run check:js
2. npm run build
3. npm run check:generated
4. npm run check:seo
5. npm run check:links

npm run build runs Webpack and then scripts/embed-gallery-captions.cjs.

.github/workflows/deploy.yml runs on pushes to main, performs npm ci, rebuilds docs/, validates the generated site, and uploads the generated docs/ directory as the GitHub Pages artifact.

Important: committed files already present under docs/ can be stale relative to source. Do not hand-edit docs/ to repair that drift. Fix the correct source/build input and let npm run build / the Pages workflow regenerate the deployment artifact.

## Shared UI and code
Root visual pages: js/menu.js is the active shared header/footer/sidebar generator.
Webpack pages: src/header.html, src/footer.html, sidebar.html plus src/js/all.js and src/js/side-foot.js are active.

css/all.css is broad/shared and high-risk for root pages. src/style/all.css is broad/shared for Webpack pages. Search selector usage before changing either.
css/animation.css contains root-page motion rules where referenced.
Heavy dependencies such as Three.js, p5, Vanta and ripples should not be expanded without a clear page purpose and mobile/performance justification.

## Change-target protocol
Identify rendered page -> classify it as root-copy or Webpack-template -> trace shared navigation/styles/scripts -> search shared selector/function consumers -> define expected delta -> edit the narrowest authoritative source -> build -> verify generated parity -> verify affected pages/viewports.

Never infer the target from a filename alone and never patch docs/ as a shortcut when a source/build path exists.
